# アルゴリズム

2次元ドロネー三角形分割 (Delaunay triangulation) を、Bowyer–Watson 法による逐次挿入法 (incremental insertion) で構成します。

実装は [`src/delaunay2d/bowyer_watson.rs`](../src/delaunay2d/bowyer_watson.rs) です。3D 四面体分割 (tetrahedralization) は未実装で、最後に方針だけ記します。

## 1. ドロネー条件

点集合 $P$ の三角形分割 $T$ がドロネー分割であるとは、

> $T$ のどの三角形についても、その外接円 (circumcircle) の**内部**に $P$ の点が存在しない

ことをいいます。これを空円条件 (empty circumcircle condition) と呼びます。

「内部」が本質的です。円周上 (cocircular) の点は違反ではありません。したがって4点以上が同一円周上にある配置では、ドロネー分割は**一意に定まりません**。正方形の4頂点はどちらの対角線を引いても条件を満たします。

## 2. Bowyer–Watson 法の考え方

点を1つずつ加えていき、加えるたびに壊れた部分だけを作り直します。

点 $p$ を追加したとき、ドロネー条件に違反するのは「外接円が $p$ を含む三角形」だけです。それらをまとめて削除すると、多角形状の空洞 (cavity) が空きます。この空洞の境界の各辺と $p$ を結べば、再びドロネー分割になります。

空洞が**星形領域 (star-shaped region)** になること、つまり境界のすべての辺が $p$ から見通せることが、この手順が正しく機能する根拠です。一般の位置 (general position) では成り立ちますが、退化配置では数値誤差により崩れることがあります（§6）。

## 3. 手順

```text
入力: 点列 P = [p_0, ..., p_{n-1}]

1. 入力を検証する（§4）
2. P をすべて内部に含む super triangle S を作り、その3頂点を
   頂点配列の末尾に追加する
3. メッシュを S ただ1つの三角形で初期化する
4. for i in 0..n:
       insert(mesh, p_i)
5. S の頂点を1つでも含む三角形を削除する
6. S の3頂点を頂点配列から削除する

insert(mesh, p):
    bad     <- { t in mesh : incircle(t.a, t.b, t.c, p) > 0 }
    counts  <- 各辺の出現回数を bad の中で数える（節点番号をソートしたキーで）
    cavity  <- { e : counts[e] == 1 }
    mesh    <- mesh \ bad
    for (u, v) in cavity:
        新しい三角形 (u, v, p) を作り、その場で CCW に再配向して mesh に追加
```

### 手順6が「その場で」でなければならない理由

擬似コードの最後の行が、この実装で最も間違えやすい箇所です。

`incircle` は、第1〜第3引数が反時計回り (CCW) であるときにのみ「正 = 内部」を意味します（[docs/predicates.md](predicates.md)）。そして `incircle` は挿入ループの**途中**、`insert` の1行目で呼ばれます。

つまり、次の点を挿入する時点で既に全三角形の向きが正しくなければなりません。向きの統一を全処理の最後にまとめて行う実装は、ループ中ずっと `incircle` の判定が反転したまま走ることになります。クラッシュはせず、間違ったメッシュが出てきます。

本実装では [`Mesh2::push_oriented`](../src/delaunay2d/mesh.rs) が三角形をメッシュに入れる唯一の経路で、そこで必ず `orient2d` により再配向します。

### 空洞境界の抽出について

境界辺を数えるとき、辺は「小さい節点番号を先にした」正規化表現 (normalized form) をキーにします。逆向きに辿られた同じ辺を同一視するためです。

この正規化表現は**同一性の判定にのみ**使い、幾何的な計算には決して渡しません。向きの情報が失われているためです。新しい三角形は `(u, v, p)` の順序を信用せず、`orient2d` で再配向します。

2D ではこの区別を守るのは容易ですが、3D では面 (face) の向きがソート済み表現から復元できないため、より重要になります（§7）。

## 4. 入力の検証

三角形分割が原理的に存在しない入力は、panic ではなく `Result` の `Err` を返します。

| 条件 | エラー |
| --- | --- |
| 3点未満 | `TooFewPoints` |
| NaN / 無限大の座標 | `NonFiniteCoordinate` |
| 座標が完全一致する点 | `DuplicatePoint` |
| 全点が共線 (collinear) | `AllPointsCollinear` |

共線判定は $O(n)$ で済みます。重複点を除外済みなら $p_0, p_1$ は相異なるので、この2点が定める直線が唯一の候補です。他のどの点もこの直線から外れなければ、全点共線です。

一方、内部バグ（空洞に境界がない、生成した三角形の向きが負など）は `debug_assert!` で検出します。呼び出し側にできることがない失敗を `Result` にしても意味がないためです。

## 5. super triangle

### 構成

入力の bounding box の中心と最大辺長 $d$ から作ります。

```
center = bbox の中心
reach  = SUPER_TRIANGLE_SCALE * d

頂点: (cx - reach, cy - d), (cx + reach, cy - d), (cx, cy + reach)
```

3頂点を頂点配列の**末尾**に追加するのが要点です。こうすると最後に削除しても、入力点の番号が一切ずれません。出力の `node0..` が入力の `id` とそのまま一致するのはこのためです。

### 大きさの決め方 — これは経験則です

全入力点を内部に含むだけなら、2倍もあれば十分です。しかし本当に必要な条件はもっと強く、

> **入力点だけからなる三角形の外接円の中に、super triangle の頂点が入ってはならない**

です。入ってしまうと、本来生成されるべき三角形が生成されず、手順5で super triangle 由来の三角形を削除した後、凸包 (convex hull) の縁に穴が残ります。

厄介なのは、この失敗が局所的な検査をすべて通過することです。向き、辺の出現回数、空円条件のいずれも満たしたまま、**総面積だけが凸包面積に足りない**という形で現れます。

凸包上の3点が共線に近づくほど外接円は無制限に大きくなるため、**有限の倍率では保証になりません**。余裕の問題です。ランダム入力480ケース（10〜500点 × 80 seed）で、総面積が凸包面積と一致しなかった件数は次のとおりでした。

| 倍率 | 失敗数 |
| --- | --- |
| 20 | 多数 |
| 1e3 | 9 / 480 |
| 1e4 | 1 / 480 |
| 1e5 | 0 / 480 |
| 1e6 | 0 / 480 |

現在は 1e6 を採用しています。

大きくすることの代償は見た目ほど大きくありません。入力点だけで構成される三角形に対する述語は、super triangle の座標を一切見ないため、精度は影響を受けません。大きな数値が現れるのは super 頂点が絡む判定だけで、それはまさに拡大が解決しようとしている対象です。

### 根本的な解決策

倍率を大きくすることは、super 頂点を**無限遠点 (point at infinity)** に近づける操作です。ならば最初から無限遠点として、数値ではなく**記号的 (symbolic)** に扱えばよいことになります。

具体的には、super 頂点を含む三角形に対する `incircle` を、通常の行列式ではなく専用の規則で判定します。これにより定数が不要になり、この節の制限は消えます。実装コストが上がるため初版では採用していませんが、次に取り組むべき改善です。

## 6. 退化配置での破綻

§2 で述べた星形領域の仮定は、退化配置では成り立たなくなることがあります。

具体例として、正六角形の6頂点と中心点を与えると、**三角形が1つ欠けた結果**になります。6頂点は厳密に同一円周上にあるため、外周のどの三角形も同じ外接円を持ちます。本来 `incircle` はゼロを返すべきところ、`f64` では丸め誤差を返し、その符号は配置ごとにばらつきます。結果として選ばれる bad triangles の集合が連結な星形領域にならず、空洞の境界が正しく閉じません。

半径を `1e-15` だけずらして厳密な共円性を崩すと、6個そろいます。**アルゴリズムの誤りではなく、述語の限界**であることがこれで分かります。

この2つのケースは `tests/degeneracy.rs` に並べて残してあります。

## 7. 3D への拡張（未実装）

構造は 2D と同じで、置き換えは次のとおりです。

| 2D | 3D |
| --- | --- |
| 三角形 (triangle) | 四面体 (tetrahedron) |
| 辺 (edge) | 三角形面 (face) |
| 外接円 (circumcircle) | 外接球 (circumsphere) |
| `orient2d` / `incircle` | `orient3d` / `insphere` |
| super triangle | super tetrahedron |

空洞の境界は「bad tetrahedra の面のうち1回しか現れないもの」になります。

### 3D 固有の注意点

**面の向きはソート済みキーから復元できません。** 2D の辺なら、2点と挿入点から三角形を作って `orient2d` で向きを直せば済みますが、3D でも同様に、面の3節点をソート済みのまま使ってはいけません。新しい四面体は必ず `orient3d` で再配向します。

また、開発中の検査として次を確認できるようにすると、破綻を早く発見できます。

- 挿入点を含む非退化な要素が生成されている
- 空洞の境界が閉じた多様体 (manifold) になっている（各境界辺が境界面にちょうど2回現れる）
- すべての四面体が正の向きを保っている
